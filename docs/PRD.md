## 1. 제품 개요

### 1.1 한 줄 정의
"이번 주 토요일 홍대 근처에서 친구 셋이 무서운 거 하고 싶어" 라고 치면, AI가 **지금 열려 있는 할로윈 이벤트**와 **공포체험·방탈출·호러 테마 공간**을 골라 지도에 찍고, 근처 저녁·카페까지 묶어 **코스**로 보여준다.

### 1.2 왜 지금 (ASSUMED)
- 할로윈 이벤트는 **기간 한정**(보통 10월 중순~11월 초)이라 "지금 어디서 하는지"가 핵심인데, 정보가 놀이공원·쇼핑몰·지자체 공지·SNS에 흩어져 있다.
- 공포 방탈출·호러 체험관은 지도 검색으로 찾을 수 있지만, 이벤트·식사와 이어진 동선은 사람이 직접 짜야 한다.

### 1.3 핵심 가치
1. **시즌 한정 정보** — 기간 안의 할로윈 이벤트만 보여준다 (끝난 행사는 숨김)
2. **오싹 → 쉬어가기 코스** — 공포체험 후 근처 저녁·카페까지 도보 동선으로
3. **진짜 있는 곳만** — 장소는 카카오 검색 결과, 이벤트는 출처 링크가 있는 것만
4. **즐겁게 무섭게, 안전하게** — 귀엽고 으스스한 톤, 실제 폐가 같은 위험한 곳은 추천하지 않음 (BR-005)

### 1.4 "흉가" 해석 (중요 — OQ-010)
요청하신 "흉가"는 **합법적으로 운영되는 체험 공간**(호러 체험관, 공포 테마 방탈출, 놀이공원 호러 메이즈·귀신의 집, 공포 테마 카페 등)으로 한정하는 것을 제안합니다. 실제 폐가·폐건물은 무단침입·붕괴·사고 위험이 있고, 서비스가 그런 곳을 안내하면 법적 책임 소지도 생깁니다.

### 1.5 범위 밖 (PROPOSED)
- 예약·결제, 티켓 판매, 회원가입, 커뮤니티·리뷰 작성

## 3. 데이터·API

### 3.1 카카오 (장소·지도) — 2026-10-23 확인
| 구분 | 엔드포인트 | 키 | 용도 |
|---|---|---|---|
| 지도 Web SDK | `//dapi.kakao.com/v2/maps/sdk.js?appkey=JS키&libraries=services,clusterer` | JS 키(도메인 등록) | 지도·마커·코스 선 |
| 키워드 검색 | `GET /v2/local/search/keyword.json` | REST (`Authorization: KakaoAK`) | "홍대 공포 방탈출", "롯데월드" 등 |
| 카테고리 검색 | `GET /v2/local/search/category.json` | REST | 코스 지점 주변 FD6 음식점·CE7 카페 |
| 도보/대중교통 경로 | `GET /v2/routing/walk` · `/publictraffic` | REST | 코스 구간 이동시간 (일 1,000건 무료) |
| 지도 URL | `map.kakao.com/link/to/...` | — | "카카오맵에서 길찾기" |

- 파라미터: `query`, `category_group_code`, `x,y`, `radius ≤ 20000`, `page ≤ 45`, `size ≤ 15`, `sort=accuracy|distance`
- 응답: `id, place_name, category_name, category_group_code, phone, address_name, road_address_name, x, y, place_url, distance`
- 쿼터: 검색 각 10만/일(초과 2원/건), 지도 30만/일, 경로 1,000/일(초과 10원/건), 월 합산 300만. 무료는 계정의 첫 활성화 앱만
- **제약**: 사진·평점·영업시간 없음 / **응답 저장 금지(실시간 호출만)** / 자동차 길찾기 REST 없음(URL 링크) / API 기능 유료화 금지
- 공포체험 공간은 전용 카테고리가 없음 → **키워드 검색**("공포 방탈출", "호러 체험", "귀신의 집", "공포 카페")으로 찾는다

### 3.2 할로윈 이벤트 데이터 (카카오에는 없음 — OQ-003 Critical)
| 출처 | 방식 | 장점 | 한계 |
|---|---|---|---|
| A. PO 큐레이션 `content/halloween-events.json` | 이벤트명·장소명·기간·출처 URL을 직접 정리, 장소 좌표는 카카오로 실시간 조회 | 정확, 우리 데이터라 저장 가능 | 사람 손, 수십 건 규모 |
| B. 한국관광공사 TourAPI 행사정보(KorService2 `searchFestival2`) | 기간(10~11월)으로 조회 후 "할로윈" 필터 | 공식·무료(개발계정 1,000건/일) | 지자체 축제 위주, 상업 이벤트 적음 |
| C. Gemini + Google 검색 그라운딩 | 질문 시점에 최신 이벤트를 검색해 출처와 함께 | 최신 | 비용·정확도 검증 필요, 출처 링크 필수 |

**제안(PROPOSED)**: 출시 버전은 **A를 주력 + B 보조**, C는 P2 실험. 이벤트 카드는 출처 링크와 기간이 없으면 노출하지 않음(BR-002).

### 3.3 AI (Gemini — CONFIRMED)
서버에서만 호출(`GEMINI_API_KEY`, 개발자 B 보유). ① 의도 추출 ② 후보(카카오 결과 + 이벤트 목록) 안에서만 선택·코스 구성·한 줄 설명.

## 4. 사용자 흐름

```
[홈]  밤하늘 그라데이션 + 달 + 캐릭터 + "할로윈, 어디서 놀까?" + 예시 칩 + D-day 배지
  │  채팅 (토글: 오싹 / 이벤트 / 쉬어가기)
  ▼
[AI 해석]  지역·날짜·인원·동행(아이?)·공포 강도 → 부족하면 1번 되묻기
  ▼
[서버]  이벤트 목록(기간 필터) + 카카오 키워드 검색(공포체험) + 주변 맛집·카페
  ▼
[AI]  후보 안에서만 3~6곳 + 코스 1개(2~4 정류장) + 한 줄씩
  ▼
[결과]  지도(번호 마커 + 코스 선) + 카드 탭(코스 / 오싹 / 이벤트 / 쉬어가기)
  │  카드: 카카오맵 보기 · 길찾기 · 이벤트 출처 · 찜
  ▼
[내 할로윈 코스]  찜 → 순서 바꾸기 → 공유 링크
```

| ID | 화면 | 핵심 |
|---|---|---|
| S1 | 홈 | 밤하늘·달 그라데이션, 캐릭터, D-day("할로윈까지 8일"), 예시 칩, 채팅바 |
| S2 | 대화+결과 | 버블, 코스 카드(정류장·이동시간), 카테고리 카드 |
| S3 | 지도 | 카카오맵, 종류별 마커, 코스 폴리라인, 바텀시트 |
| S4 | 내 코스 | 찜·순서·공유 |
| S5 | 상태 | 로딩(유령이 지도 위를 둥둥), 결과 없음(검은 고양이 갸웃), 오류, **시즌 종료 안내**(11월 이후) |

### 8.1 `/api/chat` 처리
1. 입력 + 히스토리 + 토글(kinds) 수신 → 2. Gemini ① 의도 추출(JSON)
3. 이벤트 목록에서 **오늘~요청 날짜 기간** + 지역 필터
4. 카카오 키워드 검색: 공포체험(키워드 4~5개 중 2개), 이벤트 장소 좌표, 코스 지점 반경 1km 맛집·카페
5. Gemini ② 후보 ID 안에서만 선택 + 코스 순서 + 한 줄 설명 → 서버 ID 검증
6. (P1) 코스 구간 도보 경로 API → 이동시간
7. 응답 (계약: `src/lib/contracts/`)

예상: 질문 1회당 카카오 3~6건 + Gemini 2회.
